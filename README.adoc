== What this state shows

A text analyzer as two Java modules from a single POM, with the two problems left open by _https://maven.aschemann.net/blog/2026/01/27/modular-basics/[Your First Modular Java Project with Apache Maven 4]_ solved.

Module resources are copied into the right module output with an explicit `maven-resources-plugin` execution, and `maven-jar-plugin` is configured per module so the build produces `analyzer-<version>-core.jar` and `analyzer-<version>-cli.jar` instead of one archive holding both.
Both are workarounds for gaps in the plugins of the day, and the article says so.

== Layout

[source]
----
src/
├── net.aschemann.maven.demos.analyzer.core/    Java module: domain model + services
└── net.aschemann.maven.demos.analyzer.cli/     Java module: command-line interface
pom.xml                                         Maven 4 module source hierarchy
----

== Building

[source,bash]
----
./mvnw package
----

To run it against a text file, here its own README:

[source,bash]
----
./mvnw prepare-package
java --module-path "target/classes:target/lib" \
     --module net.aschemann.maven.demos.analyzer.cli/net.aschemann.maven.demos.analyzer.cli.AnalyzerCommand \
     README.adoc
----
